## Phase 4 notes — COMPLETED 2026-09-02
- **Blueprint internal tension (flag per rule 2/6 → resolved):** §6.3 wants `location_pings` partitioned monthly AND §6.1 lists global `idempotency_key (unique)`. Postgres forbids a unique/PK on a RANGE-partitioned table unless it includes the partition key, so both cannot coexist on one table. **Decision:** make `location_pings` RANGE(createdAt)-partitioned (monthly) and preserve the §1.1 idempotency pattern via a companion `IdempotencyKey` table holding the global UNIQUE on `idempotencyKey`; `addPing` gates on it in the same transaction before writing the partitioned ping row (still returns `{duplicate:true}` on replay). `LocationPing.idempotencyKey` is retained on the row (non-unique) for observability. Migration `20260902095000_phase4_partitioning` is hand-written raw SQL (Prisma can't model partitioned tables): creates `IdempotencyKey`, drops+ncreates `"LocationPing"` as `PARTITION BY RANGE ("createdAt")` with composite PK `(id,"createdAt")` and FK to Trip, and seeds the current-month partition (drop is acceptable on dev/demo — no precious data).
- **Redis rate limiter** (`src/middleware/rateLimit.js` + `src/lib/redis.js`): Lua sliding-window over a sorted set (atomic), keyed `rl:<ip>:<route>`, SHARED across instances; **fail-open** on Redis error with a logged warning (§14.3). Same external limits (login max 10/min, global max 300/min). `config.redisUrl` from `REDIS_URL` (`.env.example` already documents it).
- **BullMQ** (`src/jobs/queues.js`, `src/jobs/worker.js`, `src/jobs/partitionMaintenance.js`, `src/jobs/retention.js`): `partition-maintenance` job calls `ensureLocationPingPartitions(monthsAhead=4)` — idempotent `CREATE TABLE IF NOT EXISTS ... PARTITION OF` using **local-calendar** month boundaries; `retention` job deletes expired refresh/reset tokens + expired/used invites. Worker runs as a separate deployable `node src/jobs/worker.js`; `backend/Dockerfile` has `api` and `worker` targets. Verified end-to-end smoke: enqueued job → worker consumed → returned result.
- **Two gotchas to remember:**
  1. Partition bounds MUST use local calendar components (`yy-mm-01`), NOT `toISOString().slice()` — on this IST machine toISOString shifts month-start a day back (UTC) and created overlapping partitions (Postgres `42P17`). Use `monthStart(offset)`.
  2. Existence checks MUST query `pg_class WHERE relname = $1` (exact, case-preserving), NOT `to_regclass('Name')` which case-folds and misses the mixed-case `LocationPing_YYYY_MM` partitions.
- **Test-runner flags added** to `npm test`: `--test-force-exit` (persistent ioredis connection keeps the event loop alive otherwise) and `--test-concurrency=1` (multiple test files share one Postgres+Redis; parallel child processes clobber each other's `before()` teardown). New tests: `tests/jobs.test.js` (partition-maintenance creates next month's partition + retention cleanup) and `tests/redis-limit.test.js` (two instance-apps share one Redis bucket — instance B reaches 429 after only 8 hits on A, proving not-per-instance).
- Deps added: `bullmq@6.3.4`, `ioredis@6.0.0`. `npm test` → **25 pass / 0 fail**. Lint clean.
